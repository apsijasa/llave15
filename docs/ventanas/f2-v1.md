# Ventana de publicación V1 · Fase 2

Primera de las tres ventanas de la fase 2 (`blueprints/vector-taller-f2/blueprint.md` §12). La prepara la sesión coordinadora; **publica el dueño**. Claude nunca toca producción.

## Qué trae

Etiqueta `f2-17` (pasos F2-00 a F2-16):

- **Inventario:**
  - productos, movimientos de stock y ajuste manual con motivo en tablet;
  - alerta de stock mínimo en `/taller` y en el resumen diario;
  - importación inicial desde CSV con `pnpm inventory:import`.
- **Compras:** proveedores y órdenes de compra. Al recibir una compra, el stock sube y el costo promedio se recalcula.
- **Repuestos de la orden ligados a productos del inventario:**
  - descuentan stock al agregarse y lo devuelven al anularse;
  - el costo queda congelado en la línea y solo lo ven dueño y administración.
- **Precios netos e IVA:**
  - columnas de régimen en órdenes y sucursal;
  - desglose Neto / IVA (19%) / Total en pantallas, correos, informe y aprobaciones de las órdenes `neto`;
  - interruptor en `/taller/catalogo`.

  El interruptor llega **en `final`**: mientras nadie lo cambie, todas las órdenes se comportan como hoy.
- **Permisos:** siete acciones nuevas (`inventory.view`, `inventory.adjust`, `purchases.manage`, `sales.record`, `expenses.record`, `cash.open_close`, `costs.view`).

## Migraciones

Una sola migración nueva en esta ventana: **`0028_absurd_sleeper.sql`**. Es solo aditiva: no tiene ningún `DROP` ni `RENAME`.

Crea las tablas `products`, `stock_movements`, `suppliers`, `purchase_orders` y `purchase_order_items`, con sus índices y restricciones.

Agrega columnas:

| Tabla | Columnas | Valor por defecto |

| | `subtotal_clp`, `vat_clp` | `0` |
| `work_order_items` | `product_id`, `unit_cost_clp` | nulos |
| `branches` | `next_purchase_number` | `1` |
| | `new_order_pricing_mode` | `'final'` |

Producción ya tiene aplicadas hasta la `0027`, de la Etapa A, publicada el 13-11-2026.

## Precondiciones

1. Taller cerrado: nadie usando `/taller` ni reservando en ese momento.
2. Respaldo de la base de producción del día, en Replit → *Database* → puntos de restauración.
3. `main` en el tag `f2-17` (o posterior), con `pnpm gate` en verde en el Mac, y subido a GitHub.
4. El régimen de precios queda en `final`. Pasar a precios netos (corte C2 de §9.1) es una decisión posterior del dueño: primero hay que confirmar que el catálogo está cargado en netos.

> Si publicas varias ventanas juntas, por ejemplo al terminar toda la fase 2, los pasos son los mismos. `db:migrate` aplica todas las migraciones pendientes en orden. Las precondiciones aplican igual, y conviene revisar también `docs/ventanas/f2-v2.md` y `f2-v3.md`.

## Pasos en Replit

En la pestaña **Shell** del workspace (no en el sitio publicado), uno por uno:

```bash
git fetch origin
```

```bash
git reset --hard origin/main
```

```bash
git log --oneline -1
```

Confirma que el último commit coincide con el de GitHub.

```bash
corepack pnpm@12.4.2 install --frozen-lockfile
```

```bash
corepack pnpm@12.4.2 db:migrate
```

Los avisos `NOTICE` ("already exists") son normales.

```bash
corepack pnpm@12.4.2 db:check
```

Debe responder `{"ok":true,...}` y listar `products`, `stock_movements`, `suppliers`, `purchase_orders` y `purchase_order_items`.

```bash
rm -rf node_modules
```

Después: **Deployments → Republish**. Si Replit muestra cambios de esquema, deben ser solo agregados. Si aparece algo marcado como destructivo, no aceptes y avisa.

## Verificación después de publicar

En el panel **Database** de producción, solo lectura:

```sql
select count(*) from products;
```

Responde sin error: la tabla existe.

```sql
select new_order_pricing_mode from branches;
```

Debe decir `final`.

En el sitio publicado, como dueño:

- `/taller/inventario` abre y muestra la lista vacía.
- El menú tiene el grupo "Inventario y caja".
- `/taller/catalogo` muestra el régimen "Precios finales".
- Una orden existente se ve igual que antes, sin desglose de IVA.
- `https://vectorbikes.cl/api/health` responde `{"ok":true,"db":true}`.

## Reversión

Republicar el deployment anterior desde Replit → *Deployments*. El esquema solo creció: el código anterior ignora las tablas y columnas nuevas, y las columnas nuevas tienen valores por defecto que no afectan a las órdenes existentes. No se revierte la migración.
